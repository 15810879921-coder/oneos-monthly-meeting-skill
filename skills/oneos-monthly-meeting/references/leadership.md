# 给领导讲清楚

## 一页只回答一个业务问题

先说“这个模块做到了什么、对业务有什么用”，需要时再说“还差什么、接下来怎么办”。每项通常一两句话。纯进展不强造卡点、拍板题或固定套话；真正影响使用、时间或资源的风险必须简短说清。

- 主管进展：结果 → 影响进展的卡点（有才讲）→ 下一步。负责人、日期只用已有依据。
- 决策层简报：先给最重要的结果，一句说明业务价值，需要取舍才补建议与待决定事项。
- 知会、征求意见、请求协调、需要决策分清。未实际对齐，不写“双方一致认为”。
- 事实、判断、计划在内部区分；正文以准确动词表达，不把核验清单、来源解释搬上 PPT。
- 缺证据不能反推别人没有做事。先窄查；仍影响结论时问一个关键事实。非重点可省略，重大风险不能隐藏。

## 去技术词和套话

| 原句 | 应怎样写 |
| --- | --- |
| 对应 4 个迭代记录／当期新建，不等于全部交付 | 删除这类过程解释，按核实情况写模块的具体进展 |
| 集中完成开发联调 | 已完成主要功能，正在检查业务流程（仅在事实支持时） |
| 跨端完成上线结果 | 电脑端和手机端已可使用某项功能（仅在确已上线时）；否则写计划上线哪些模块 |
| 持续赋能、全面打通、闭环落地 | 直接写谁能做什么、哪件事更方便；没有具体事实就删掉 |
| 需求—交付—开发—测试各 X 条 | 将同一业务工作合并讲，计数和正式关系留在内部依据 |

这些是翻译方法，不是机械替换表。不得为了人话改动事实阶段；不逐条朗读工单标题、编号、版本号或接口名称。正文保留 ONEOS 品牌，口播统一说“系统”。

## 目录和子页

先按实际内容分章节，再把工作放回对应模块。示例层级（仅展示组织方法）：

```text
1 重点建设
  合同管理：本月完成的具体工作
  车辆管理：本月完成的具体工作
2 运行与配合
  业务支持：解决了什么问题
3 下月目标
  三个里程碑：每批的上线模块和用途
```

同一个模块跨多个迭代或有电脑端、手机端任务，先归并，再按确有差异的使用结果说明。禁止按取数返回顺序逐项报数。

## 下月计划：三个里程碑

先读取使用者提供的原始计划，建立内部映射“原话 → 模块 → 预期可用功能 → 依赖／有依据的时间 → 所属批次”。按依赖先后和业务价值拆成三批，必要时将大模块分为有业务意义的可用范围，但必须能回溯到原计划，不新增功能范围。

每批用一句话：“第一批：上线〔具体模块〕，可以〔业务动作〕。”有已提供的日期才替换为日期；只有建议顺序则标“建议安排”。不要把“完成开发、完成联调、跨端上线”当三个里程碑。11 月目标同样必须说明三批各上线什么。

计划完全没给，问“下个月准备上线哪些模块？直接说内容即可。”只有模糊目标，先整理已给内容，再只问缺少的模块或取舍。计划不足以合理分为三批时，不凑数量、不编模块；本月部分继续完成，计划部分保留为待补稿，不交付冒充完整的最终视频。
